No-Show Card Game — Requirements Document
1. Product Overview
No-Show is a strategic card game where players compete to have the lowest hand score. The goal is to be the last player remaining with a total score under 100. Players take turns throwing cards and picking new ones, form valid combinations to reduce their hand value, and may call "Show" when confident they have the lowest score.

2. Game Modes
2.1 VS System (Solo vs AI Bots)
Description: A single human player plays against AI-controlled opponents.
Player count: 3–6 total (1 human + 2–5 bots).
Setup: User selects their name and number of bots (2–5).
Behavior: Bots take turns automatically with simulated thinking delay. Bots use strategy to minimize hand score and decide when to call Show.
2.2 Multiplayer (Play with Friends)
Description: Human players create or join a room using a room code.
Player count: 3–6 players.
Room creation: User creates a room and receives a unique 6-character alphanumeric room code.
Room joining: Other players enter the room code to join.
Room capacity: Maximum 6 players per room.
Start conditions: Minimum 3 players required. All players (including owner) must mark themselves as "Ready" before the owner can start the match.
Room owner: The creator is the owner. Only the owner can start the match.
2.3 Online (Match with Players Worldwide)
Description: Players are matched with random opponents via a matchmaking queue.
Player count: User selects 3, 4, 5, or 6 players.
Matchmaking: Players join a queue; when enough players with the same desired count are available, a game is created.
Auto-fill: If wait time exceeds a threshold (e.g., 60 seconds), remaining slots may be filled with bots given human-like names.
3. Core Game Rules
3.1 Deck and Card Values
Deck: Standard 52-card deck (4 suits: hearts, diamonds, clubs, spades; 13 ranks: A, 2–10, J, Q, K).
Card values:
Ace (A) = 1
2–10 = face value
Jack (J) = 11
Queen (Q) = 12
King (K) = 13
Order (for sequences): A < 2 < 3 < … < 10 < J < Q < K
3.2 Game Setup (Each Round)
Deal: Cards are shuffled and dealt in rotation.
Starter: One random player receives 8 cards; all others receive 7 cards.
First player: The player with 8 cards starts the round.
Deck: Remaining cards form the face-down draw pile.
Open card: One card is placed face-up as the initial "last thrown" / available card for the first player to optionally pick.
3.3 Turn Structure
Each turn has two phases:

Phase 1: Throw
Player must throw one or more cards from their hand.
Valid throws:
Single card: Any one card.
Pair or more of same rank: 2+ cards of the same rank (e.g., K-K, 7-7-7).
Sequence of 3+ consecutive ranks: 3+ cards in ascending order (e.g., 7-8-9, J-Q-K). Suit does not matter. No gaps allowed (e.g., 2-4-5 is invalid).
Thrown cards become the "last thrown" pile and are available for the next player to pick from.
Phase 2: Pick
After throwing, the player must pick exactly one card.
Pick options:
From deck: Draw the top card from the face-down deck.
From last thrown: Pick any one card from the cards just thrown by the previous player (or the initial open card for the first player).
The player adds the picked card to their hand.
Turn passes to the next active (non-eliminated) player in clockwise order.
3.4 Show
When available: A player may call "Show" only after each active player has completed at least one full turn in the current round.
Action: On their throw phase, before throwing, the player may press "Show" to reveal all hands and resolve scoring.
Scoring when Show is called:
All players reveal their hands.
Hand score = sum of card values in hand.
If the caller has the lowest hand score:
Caller adds 0 to their total.
Each other player adds (their hand score − caller's hand score) to their total.
If any other player has a lower or equal hand score:
Caller receives a +15 penalty added to their total.
All other players add 0 to their total.
3.5 Elimination
Threshold: Any player whose total score reaches or exceeds 100 is eliminated.
Effect: Eliminated players no longer participate in subsequent rounds. They are skipped in turn order.
3.6 Round End and Next Round
After Show is resolved, the round ends.
If only one player remains (all others eliminated), the game ends and that player wins.
Otherwise, a new round begins:
New deck shuffled and dealt.
One random active player receives 8 cards and starts.
Show is locked again until each active player completes one turn.
3.7 Game Over
Win condition: The last player with a total score under 100 wins.
Tie: If all remaining players are eliminated in the same round, the player with the lowest score wins.
4. Functional Requirements
4.1 User Authentication
Users must be able to sign up and log in.
Users must have a unique identity (e.g., user ID) for multiplayer and online modes.
Users must have a display name or username used in games.
Users must be able to change their username (stored and synced).
4.2 Home Screen
Display the game title and branding.
Provide access to: VS System, Multiplayer, Online.
Provide access to "How to Play" rules.
Provide access to user profile (e.g., profile icon).
Profile panel must allow: view username, change username, add friends (UI only / placeholder).
4.3 VS System Flow
User selects their name and number of bots (2–5).
Game starts with one human and selected number of bots.
Bots take turns automatically with visible "thinking" feedback.
User can see their hand, opponents' card counts, deck count, and last thrown cards.
User can select cards and throw, or pick from deck/available.
User can call Show when allowed.
Game proceeds until one player wins.
User can play again (same bot count) or return home.
4.4 Multiplayer (Room) Flow
Room Creation
User enters display name.
User creates a room.
System generates a unique 6-character room code.
User is taken to the room lobby.
User can share the room code (e.g., via system share).
Room Joining
User enters display name and room code.
User joins the room.
User is taken to the room lobby.
Room Lobby
Display list of players with: display name, owner badge, ready status.
Non-owner players must press "Ready" to indicate they are ready.
Owner sees "Start match" only when: at least 3 players are in the room AND all players (including owner) are ready.
Owner can start the match.
When started, all players are taken to the game screen with the same game state.
During Game
All players see the same game state in real time.
Each player sees only their own hand.
Players see opponents' names and card counts.
Turn indicator shows whose turn it is.
Players can quit; others receive a notification (e.g., "X left the game").
If only one player remains (others quit), that player is returned to home with a message.
4.5 Online (Matchmaking) Flow
User selects desired player count (3, 4, 5, or 6).
User joins matchmaking queue.
System matches players with the same desired count.
If wait exceeds a threshold, remaining slots may be filled with bots.
When match is found, all players enter the game.
Game behavior is the same as room-based multiplayer.
4.6 Game Screen (In-Play)
Header: Round number, current player/turn indicator, quit (X) button, scores access.
Deck: Face-down pile with remaining card count.
Last thrown: Face-up cards from the previous player's throw (available to pick from).
Opponents: Each opponent's name and card count. Cards shown face-down.
Player hand: User's cards, sorted (e.g., descending: K, Q, J, 10…A).
Actions (when it's the player's turn):
Select cards, then "Throw" (validates selection).
Or "Pick from deck" / "Pick from available" (after throw phase).
"Show" button when allowed and no cards selected.
Scorecard: Modal showing all players' scores, round number, eliminated players, and players who left.
Active player count: Display "X/Y active" (e.g., 3/3, 2/2 after someone leaves).
Quit: User can quit; confirmation required. In multiplayer/online, other players are notified.
4.7 Show Reveal
When Show is called, all hands are revealed.
Display each player's hand score and points added this round.
Show scoring formula (e.g., "You: 0 | Others: their_score − your_score" or "You: +15 penalty").
Provide "Next Round" or "See Results" (if game over).
4.8 Results Screen
Display final rankings (sorted by score).
Highlight the winner.
Provide "Play Again" (same mode/setup) and "Home" options.
For VS System: Play Again restarts with same bot count.
For local PvP: Play Again restarts with same player names.
4.9 How to Play
Provide a scrollable rules reference.
Include: objective, setup, turn structure, card values, Show rules, elimination, valid combos (sequence, pair).
4.10 Player Leave Handling (Multiplayer/Online)
When a player quits, other players receive a notification (e.g., pop-up: "X left the game").
Active player count updates (e.g., 3/3 → 2/2).
Scorecard shows a "Left Game" section for players who quit.
If only one player remains, that player is notified and returned to home (e.g., "All other players left. Returning to home…").
5. Non-Functional Requirements
5.1 Real-Time Synchronization
Multiplayer and online games must keep all clients in sync with the same game state.
Actions (throw, pick, show, next round) must be reflected for all players within a reasonable delay.
Disconnections should be handled (e.g., player marked as left, others notified).
5.2 Responsiveness
UI must respond to user input without noticeable delay.
Bot turns should have a short, visible delay to simulate thinking.
Loading states must be shown for network operations (create room, join, matchmaking).
5.3 Accessibility
Text must be readable.
Touch targets must be adequately sized for mobile.
Critical actions (Throw, Show, Pick) must be clearly visible and accessible on small screens.
5.4 Error Handling
Network errors (e.g., cannot reach server) must show a clear message.
Invalid actions (e.g., invalid throw) must be rejected with feedback.
Failed room creation/join must show an error message.
5.5 Data Persistence (Where Applicable)
User profiles (username) must persist.
Room and game state may be ephemeral or persisted as needed for the session.
Game history and statistics may be recorded for VS System and multiplayer/online games.
6. Card Display and Ordering
User hand: Cards displayed in descending rank order: King, Queen, Jack, 10, 9, 8, 7, 6, 5, 4, 3, 2, Ace.
Opponent hands: Shown as face-down cards with count. Individual card values are not visible to others.
Last thrown: Face-up so the next player can choose which card to pick.
Deck: Face-down with count of remaining cards.
7. Scorecard Requirements
Display round number.
List active players with current score and turn indicator.
List eliminated players with "OUT" status.
List players who left the game with "LEFT" status.
Opponent hand scores (sum of cards in hand) are only visible during Show reveal, not during normal play.
8. Validation Rules
Throw: Must be exactly one of: single card, 2+ same rank, or 3+ consecutive ranks.
Pick: Must pick exactly one card from deck or from last thrown.
Show: Only allowed after each active player has completed at least one full turn in the round.
Room code: 6 characters, alphanumeric (excluding ambiguous characters like 0, O, 1, I).
Display name: Trimmed, max 50 characters.
Player count: 3–6 for all multiplayer modes; 2–5 bots for VS System.
9. Edge Cases and Constraints
Deck exhaustion: When the deck is empty, the dead pile (discarded cards) is shuffled and used as the new deck.
Single active player: If only one player remains (others eliminated or left), game ends; that player wins.
All eliminated in same round: Winner is the player with the lowest score among those eliminated.
Skip eliminated players: Turn order skips eliminated players.
No skipping turns: Every player must complete their throw and pick each turn (or call Show instead of throw when allowed).
